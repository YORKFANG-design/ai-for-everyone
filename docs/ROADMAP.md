# 30 天 MVP 路线

这是 Gate 1 批准后的计划窗口，不是已承诺的发布日期。

| 阶段 | 工作 | 审核节点与完成条件 |
| --- | --- | --- |
| 第 1–3 天 | 确认定位、首页、范围 | Gate 1：负责人确认定位与首页结构 |
| 第 4–10 天 | 建立响应式原型、内容详情、往期与本地收藏 | Gate 2：移动端和桌面端核心流程可走通，示例标注明确 |
| 第 11–17 天 | 准备真实内容、建立审核发布流程 | Gate 3：至少连续 7 期内容完成来源及质量审核；缺内容不冒充每日更新 |
| 第 18–24 天 | 小范围邀请体验、收集反馈 | Gate 4：取得参与者同意，记录使用障碍和回访情况 |
| 第 25–30 天 | 分析反馈、评估收费与运营成本 | Gate 5：负责人决定继续、调整或暂停，以及是否启动付费试验 |

## 验证指标

- 激活：首次访问后完成一次技能练习的用户比例。
- 次日与第 7 日回访：首访用户在对应日期再次访问的比例；分母为已到观察日的首访用户。
- 内容完成：完成技能练习的人数 / 打开技能详情的人数。
- 付费意愿：明确表达愿意按具体价格购买的人数 / 回答该价格问题的人数。仅口头意愿不能算付费转化。
- 内容生产成本：每期编辑、核查及维护耗时。

初期目标值待基线数据与样本量确定，不填造数字。浏览器本地原型不能支持跨设备用户统计，不将其记录用于宣称真实留存。

## 风险与处理

新闻过期：保留发布时间与核查时间。工具门槛：写清账号、付费和地区限制。内容供给不足：允许回看最近一期，展示真实日期。用户不回访：先访谈核对内容需求，再增加功能。
